01 / the problem

Most agent work is not frontier work.

Agent systems spend a large share of their time on deterministic tasks: git status, directory listings, port checks, dependency reads, and basic parameter assembly. Sending every one of those jobs through a frontier model adds prompt cost, network delay, and another generated tool-call round.

Wrench treats the routine layer as an engineering surface, not a reasoning contest.

Request flow / WR-002
agent intent→Wrench draft
read-only tool→local result
draft + result→cloud review
mutation / ambiguity→escalate
02 / the model family

Two sizes. One job.

Flash is the always-on edge design target. Pro is the workstation adapter released as V21. They share the same core contract: structured tool calls, deterministic verification, and a hard line between safe routine work and work that belongs with a larger model.

TIER 1 / EDGE

03 / project status

Validated adapter. Router deferred.

The V21 Wrench-Pro adapter passed the frozen 440-case holdout, the fresh 220-case context suite, and a clean-environment package load. The result is bounded to the authored local contract and does not certify a router, hosted service, or arbitrary shell execution.

Status: weights ready for release. The adapter is distributed separately from the Git source repository.

What Wrench does not do

Not every request belongs local.

  • It does not replace a frontier model for deep planning.
  • It does not speculatively run mutations or destructive commands.
  • It does not claim human, market, or production proof from a replay.
  • It does not certify router savings, hosted serving, or production traffic.
