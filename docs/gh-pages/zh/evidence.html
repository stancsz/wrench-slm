04 / 进展与证据

活儿得干成，
账也得算明白。

更新于 2026 年 9 月 22 日。Wrench 已有一小段能工作的本地流程。普遍能省多少钱、是否能上生产，现在还没证实。

今天能说到哪儿？

固定规则工具与独立校验有本地证据
三个指定客户端通过部分有限检查
模型自由决定路线未启用
按服务商权威账单核对实际付费还没齐
同等成功任务的耗时改善尚未证实
生产发布未获批准

这里有一份能直接看的结果

网站的示例结果文件来自实际 Python 校验器：在临时目录里成功读一行，拒绝越界路径，拒绝 shell 操作，最后确认测试文件没变。

它只证明校验器在这几个例子里的行为。模型好不好、整条流程省不省钱，这份结果都没测。有仓库权限的朋友可以按入门步骤复现。

内部实验记录到了哪儿？

项目仓库已公开。下面是维护者整理的实验摘要，不等于独立复现或完整的公开基准；结论仍以对应版本的原始记录和复现条件为准。

  • 一次有限的本地影子测试完成了 200/200 个机械请求，包含并发、取消恢复、资源余量检查和结果哈希。这还不能证明生产环境的稳定性。
  • 一次带引导的备用路线实验通过了两个直接客户端和三个混合客户端。虽然记下了 token 用量，但证明实际花费所需的服务商权威账单还没齐。
  • 已经补上按客户端记录耗时的功能。接下来还要重复配对测量，不能拿一次进程耗时就说“快了”。

什么才叫真的省了？

同一份获准的任务，一边用强模型直接做，一边用 Wrench 加备用模型做。对比最终完成情况、安全性、耗时、云端 token、本地工作量、费用、重试、纠错和交接开销。

实际省下的成本 =
  基准流程成功完成这份任务的成本
  − 混合流程成功完成同一份任务的全部成本

“全部”包括付费模型调用和相关本地开销。云端 token 少了，账单不一定同比下降，包月、缓存计价、重试都会影响结果。拒绝得快，也不算把任务做得快。

目标写在这儿，别当成绩单

当前目标是在限定的评估任务中，把净强模型 token 用量降低至少 95%，同时计入校验、上下文压缩、重试、纠错和备用调用。最终任务成功率与安全性不能出现实质退步，成功任务的耗时也要明显改善。

95% 是目标，还没拿下。它不是订阅折扣，也不是“你的 AI 账单保证砍到只剩 5%”。

首页的 20× 就是把这个目标换个写法：强模型 token 用到基准的 1/20 或更少。新提出的 < 0.5% 则是更远期的云端费用愿景，对比的是云端模型基准成功完成同一任务的花费。它不是当前验收门槛，也不是实测成绩。算总成本时，本地开销仍然不能漏掉。

4M 指面向大输入的处理方向：本地检索、压缩，再交给有限的模型上下文。它不能当成原生 4M 注意力、完整记忆或全流程低延迟的证明。

下一步先补什么？

  1. 选定接受评估的备用路线，补齐成本证据，做同任务配对比较。
  2. 修好超时和慢请求，再重复测量成功任务的耗时。
  3. 看真实交接记录，挑值得做、能校验的新处理能力。
  4. 持续做运行检查，证据足够后再讨论生产启用。
