03 / 和谁搭伙

尽量接进你
已经在用的工具。

目前聚焦 OpenCode、DeepSeek Harness 和 Claude Code。先把一个有边界的“请求进来、结果回去”流程跑顺。

还是开发者预览：通过了本地的一小段检查，不等于各种版本和用法都能稳跑。目前还没有公开的一键安装或生产部署方案。
客户端现在看到的结果还差什么
OpenCode已有本地有限流程验证。之前的输出循环问题通过固定使用 1.18.32 可执行版本解决。重复的配对耗时测量，以及完整成本核算。
DeepSeek Harness已有本地有限流程验证。一次带引导的备用路线实验通过了精确答案检查。直接备用路线仍有精确答案检查失败。选哪条路线，确实有区别。
Claude Code当前本地记录中，有有限混合流程的客户端检查。更广的实际任务和持续运行验证。

接入协议，用人话说

  1. 客户端发来一个范围明确的请求。
  2. Wrench 提出允许的操作，或者拒绝。
  3. 独立校验器检查提案，再执行允许的读取或供审阅的操作。
  4. 最终回答与经过校验的结果绑定；需要升级处理时，把原请求交回配置好的备用路线。

这是一套两阶段协议：先提案，再根据已验证结果给出最终回答。它不会自己开启没完没了的工具循环。

想试自己的流程？先做这几件事

  • 先跑通不调用模型的小例子。
  • 选一个小的、不含敏感信息的工作区，明确要做哪件事。
  • 记下客户端版本、服务器配置和备用模型路线。
  • 看看最后答案对不对。HTTP 200 只说明请求回来了，没说活儿干好了。
  • 把失败、重试、本地开销和付费调用一起记账。

完整客户端实验可能需要本地模型文件和模型服务配置。免费、无 Key 的小例子不能代表这些实验的全部要求。在可复现的公开分发版本准备好之前，客户端接入仍按受控的开发者评估来做。

其他客户端和硬件呢？

新增客户端、原版 Ollama / vLLM / GGUF 适配，以及独立的硬件移植工作，目前不在这一步的执行范围。先看真实需求、跑通实际流程，再加菜单。小显存和旧手机的方向可以看路线图。
