05 / Practical questions

Before you try Wrench.

Straight answers about the project’s promise, availability, and limits.

Will Wrench be free and open?

Yes. Our commitment is clear: open source, open weights, open datasets. We will open-source the code and make the model weights and datasets available.

We want you to use it for free, understand how it works, modify it, and run it yourself. Together, we can bring AI costs down. The open release is in preparation; download links and specific licenses will be published with it.

The documented local example requires no model or paid API call; local electricity and any configured cloud fallback still have costs.

Will it lower my ChatGPT or coding-assistant subscription?

Not automatically. A flat monthly subscription stays the same unless your plan changes. The clearest cost question is whether Wrench reduces metered usage for the same completed work. It may also reduce usage pressure, but that needs workflow-specific evidence.

Do I need a new GPU?

The mission starts with people who have less than 8 GB of GPU memory. The next hardware milestone is a useful workflow below 2 GB, with older phones as a related target. These are targets, not verified support. The no-model Python example needs no GPU. See the hardware roadmap.

Can I lend my spare compute to friends yet?

Not yet. That is the longer-term vision: voluntarily share spare computing power with people you trust. No friend-to-friend compute network is implemented in the current product.

Does Wrench replace my coding assistant?

Its current role is a narrow helper for verifiable developer-tool work. Your larger workflow still handles reasoning, complex edits, and out-of-scope requests. Wrench does not autonomously implement and deploy a feature.

How is Wrench different from a coder model?

It is designed to work alongside larger models and bring total workflow costs down. The larger model handles requirements and difficult reasoning. Wrench handles bounded, repetitive steps such as file reads, exact searches, and status checks using local rules, independent verification, and restricted execution.

Those design choices do not establish universal superiority over coding models, which can also use tools and verification. Wrench must prove its value through matched task success, total cost, and latency. See the division of work →

Is abstention the main feature?

It is an important handoff mechanism: return control when scope, evidence, or verification is insufficient. The useful outcome is completing the right local work, handing back the rest cleanly, and reducing total cost. Declining everything only adds a detour. Explicit rules and independent checks currently govern this boundary; learned free-form routing remains disabled. How we evaluate it →

Why use Wrench if I already have ripgrep and Git?

Those tools already do useful local work. Wrench adds a structured proposal and verification boundary intended for AI workflows. The project must still show that this integration creates value compared with both a stronger-model baseline and simple rules plus fallback. Extra routing is only worth keeping when the completed workflow benefits.

Is all my data kept local?

The Python example makes no network calls. A workflow with a cloud fallback can send context to its configured provider. Review that client’s data flow and use a non-sensitive workspace during evaluation. This project does not claim universal offline operation.

Can Wrench change my files?

The allowed tool portfolio is read-only or review-only. A patch draft is returned for review and is not applied by this worker. The example script itself creates and cleans up a temporary fixture so you can observe the boundary.

How can I help?

Start with a concrete repetitive task: what you ask your coding assistant to do, what a correct result looks like, and where it spends time or paid tokens. Share a small sanitized example with the maintainer through your existing project contact. Do not include credentials, private code, or raw provider logs. You can also follow progress in the public project repository. A formal distribution release is still in preparation.
