## Critic pass

The report addresses the owner's three conditions directly: LoRA remains a
required proposed stage, overall effectiveness is measured at the successful
task and all-in cost level, and day-long coding is evaluated as sustained
engineering rather than a unit test score. It narrows the local role after the
0.8B failure rather than either dismissing all larger models or restarting the
same broad-agent hypothesis.

The model recommendation is deliberately conditional. Qwen3.5-4B is a
candidate for a held-out controller screen, not a qualified production model.
The published scores come from the model owner, and no Qwen3.5 LoRA composition,
serving memory, throughput, real-repository coding, or adapter performance was
measured. The 9B row has a public current tree size but no full pinned revision
in this report. The 30B coding model is excluded because its published source
snapshot alone exceeds the strict aggregate project ceiling.

## Findings and limits

- No matched real Wrench task pair exists, so the quality-retention and
  all-in-cost claims remain unmeasured. The report proposes gates; it does not
  certify a 95/95 result.
- Public tree inventory is research metadata, not local hash verification or
  a peak-byte job reservation. A later artifact job still must enumerate every
  file at the exact revision/format, count duplicates and temporary peak,
  check free disk/RAM/VRAM, and use the storage checker.
- The complete product direction remains an owner decision. The report does
  not alter E0–E4 or the prior 0.8B closure.
- This review shares an author with the report, so the critique is not an
  independent review.

## Result

**Research deliverable accepted as decision evidence only.** Recommended next
step is owner approval of a fresh, staged gateway candidate evaluation. No
