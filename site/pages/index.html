A teammate for your big model

Let local tools carry more.
Give the big model less to juggle.

Searching material, digging through long histories, locating exact text, reading configuration, and checking status all add up. Wrench aims to take the verifiable work locally and return useful evidence, leaving the larger model to interpret requirements, diagnose causes, and design changes. Built to work with big models. Built to bring AI costs down.

01 / PRECISE INPUTS

Known arguments need less guesswork.

When paths, line ranges, and search terms are explicit, local rules construct the action. Deterministic tools handle the repetitive steps without asking a model to regenerate every argument.

02 / CHECKABLE OUTPUTS

Bring back evidence of the work.

An independent verifier checks authority and arguments before a restricted executor acts. Return actual results and their sources. Patches remain drafts for review.

03 / CLEAN HANDOFFS

Know when to hand it back.

Out-of-scope or failed checks produce an abstention. The caller preserves the original request and handles fallback. The design aims to keep a small mistake from turning into expensive rework.

For a login timeout: the big model decides what to inspect → Wrench reads permitted configuration and returns evidence → the big model continues the diagnosis and proposes a fix.

These are design choices for routine work, not proof that Wrench is universally stronger, faster, or cheaper than coding models. Coders can use tools and verification too. The current path uses rules, retrieval, and checks; learned free-form routing is disabled. Explore the division of work, abstention, and evaluation →

The ambition, with the labels left on

Big models for judgment.
Small workers for the legwork.

Our long-term ambition: spend less than 0.5% of the cloud-model baseline on the same completed work, and make those remaining paid tokens count. Today’s worker starts with deterministic local tools. The full savings story still needs measurement.

Large-input direction4M

More context. Less baggage.

Work toward taking in 4M-token inputs, finding relevant evidence locally, and keeping the model’s working context bounded. Hybrid retrieval, not native 4M attention or guaranteed recall.

Current token target20×

Fewer paid tokens. Same job done.

The 95% net frontier-token reduction target means at most 1/20 of baseline usage on the evaluated workload. This is a target, with verification, retries, and fallback counted.

Long-term cost ambition< 0.5%

Make the remaining spend count.

Aim to reserve paid cloud calls for the hard parts. This is an ambition for matched-workload cloud spend, not an achieved result or a reduction in your subscription fee.

Current authority boundary0

No surprise file edits.

Zero autonomous file-write authority in the bounded worker. Read, check, and draft for review. Your files don’t become collateral damage in a cost experiment.
