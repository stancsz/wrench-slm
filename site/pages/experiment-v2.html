Experiment v2 / Design stage

Prepare the context. Learn the useful habits.

Wrench v2 is a local Layer 1 runtime before a coding agent's next model call. It prepares traceable context, exposes relevant tools and chooses when to escalate. The runtime and continual-learning system described here are planned experiments.

What Layer 1 does

Ordinary code parses repositories, builds indexes, searches, filters logs, stores exact originals and verifies boundaries. A small controller ranks evidence, decides whether to retrieve more, selects tool namespaces and proposes a permitted model route. Hot code, current diffs and exact failures stay lossless. Compressed older material keeps a reference to its original source.

Three weight components

  1. Frozen Qwen checkpoint: the starting foundation. Qwen3.5-0.8B is the candidate; its complete pinned snapshot is about 1.77 GB, before runtime and training overhead.
  2. Wrench-Core LoRA: shared product behavior, trained from curated data and frozen during use.
  3. Continuous LoRA: personal behavior learned from reviewed experience in background batches. Each candidate must pass evaluation before activation and retain a known-good rollback.

Changing code facts stay in external state. Adapters learn habits about retrieval, context and routes. Replay may reduce forgetting, but every update still needs core regression and fresh task evaluation. A learned decision never grants shell, credential or mutation authority.

What we learned from v1

The owner reports filesystem corruption and lost data. Surviving audits also show unavailable payloads, unaccepted draft data and evaluation problems. They do not establish the precise filesystem cause. V2 requires the complete model footprint, all copies, caches, checkpoints and temporary growth to remain below 50 GB total, with immutable versions, checksums, bounded retention and tested recovery.

How the experiment proceeds

  1. Build and measure the deterministic context and exact-retrieval baseline.
  2. Add the core adapter and prove a useful improvement after local overhead.
  3. Collect permitted, verified experience and evaluate a small personal adapter on later tasks.
  4. Demonstrate interruption recovery, version activation and reset.
  5. Compare complete workflows across the intended clients, including every retry, cache miss and fallback.

Retained v1 verifier and retrieval code are starting materials. The full v2 adapter stack is not implemented or measured. Token savings, task success, latency and resource use must come from matched tasks. The earlier 95% savings ambition remains a target.

Direction recorded 2026-09-23. The repository's North Star, architecture, experiment protocol and v1 learning record carry the detailed engineering plan.
